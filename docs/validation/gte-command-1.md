# Validation record: 2026-11-21 (host and SH-2 model, gte-command-1)

Function `sh2o_gte_command` in `sh2o/gte.h`: the dispatch to the 14 command functions. Each command has its own record (see [VALIDATION.md](../VALIDATION.md)).

- **Pins:** SH2ZAM `7f99eb70`, Yabause `7e38821d`, sh2eb-elf-gcc 13.2.0 in the pinned Yaul image (`ijacquez/yaul@sha256:b6d27220…`). Host compilers: GCC 16.2.1 and Clang 23.1.6.
- **Host, exact:** `make test` passes with GCC and with Clang. The test `gte` gives the 147 `cmd` vectors of `tests/gte_oracle.h` (177 for all GTE functions) with zero differences, the return code included. One vector has opcode `0Ch`, which is not modelled: the call returns -1 and does not change the image. The suite gives the digest `0xA50D51B1` over 3,840 cases (256 for each of the 14 opcodes, and 256 more MVMVA cases, one for each selector), which is its pin. The gte mutants change these counts of the 177 vectors: `shift_11` 14, `shift_13` 17, `clamp_off_by_one` 13, `unr_index_off_by_one` 1, `swapped_flag_bit` 2 (and the suite gives `0x016CD511`), `dropped_sxy_push` 11, `dropped_sz_push` 10, `dropped_colour_push` 42; of the UNR mutants, `unr_div_clamp_bound` 1. The records of the commands give the split by opcode.
- **Host, other sources:** the test `gte_sources` gives 72,397 cases (edges 13,553, LCG 57,344, ps1-tests 1,500) of all the commands through `tests/test_gte.c --driver` and the Python model: 0 differences on all 64 registers, FLAG included. The output gives the total only, not a count for each command. The test `gte_recordings` (private recordings, 75,261 cases) gave 0 differences in the record "GTE against the model" of [VALIDATION.md](../VALIDATION.md). It was not run again for this record.
- **SH-2 cross build:** `make cross`. `tests/sh2/gte_static.txt` (native, at `-Os` and `-O2`): no undefined symbol, 9 `MAC.W`, all through `sh2o_k_mvb3`; no `SETS`, no GBR, no SR write, no divide step, no constant in the SH-2 divider area. `tests/sh2/gte_switch_static.txt` (the test build with `SH2O_MVB3_SWITCH=1`): 15 `MAC.W`, the same forbidden instructions. `tests/sh2/gte_portable_static.txt` (`SH2O_FORCE_PORTABLE=1`): no `MAC.W`. `tests/sh2/gte_suite_static.txt`: the suite object needs only `sh2o_gte_read`, `sh2o_gte_write` and `sh2o_gte_command`. The planted count of `gte` and `gte_switch` is found.
- **SH-2 model, exact:** `make sh2-model`. In the native program and in the portable program, the 147 `cmd` vectors give zero differences, with SR.S = 0 (177 of 177 vectors exact in each program). Each program gives the pinned digest `0xA50D51B1` over the 3,840 suite cases, and the 14 known answers (one for each opcode) hold. Program sha256: native `d44e4d29…`, portable `9e32dfd4…`.
- **SR.S:** The harness runs each suite case and each oracle `cmd` vector again in the native program with SR.S = 1. The result is different for 493 of the 3,840 suite cases and for 5 of the 147 `cmd` vectors. The harness gives these totals for all the commands together, not a count for each command. The library does not check SR.S. These counts are not a pass or a failure. The commands that can use `MAC.W` in the native program (through `sh2o_k_mvb3`) are RTPS, RTPT, MVMVA, NCS, NCT, NCDS, NCDT and NCCS.
