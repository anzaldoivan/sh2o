# Validation record: 2026-11-21 (host and SH-2 model, psyq-ratan2-1)

Function `sh2o_psyq_ratan2` in `sh2o/psyq.h`, the contract of the PSY-Q libgte function `ratan2`: it gives the arctangent of y and x, with no GTE register access. [VALIDATION.md](../VALIDATION.md) lists the other records.

- **Pins:** SH2ZAM `7f99eb70`, Yabause `7e38821d`, sh2eb-elf-gcc 13.2.0 in the pinned Yaul image (`ijacquez/yaul@sha256:b6d27220…`). Host compilers: GCC 16.2.1 and Clang 23.1.6.
- **Host, exact:** `make test` passes with GCC and with Clang. The psyq family has no oracle file. The test `psyq` runs the suite `tests/suite/sh2o_psyq_test_suite.c`: 1,216 cases (64 for each of the 19 bodies) give the digest `0xE430E70B`, which is its pin. Of these cases, 64 are ratan2 cases. The 6 known answers of `ratan2` hold. The test `psyq_table` compares the table of `ratan2` with its formula (`scripts/psyq_tables.py`). The mutant `ratan_index_off_by_one` changes ratan2. With it, the suite returns `0x404`. Known answer 3 of `ratan2` fails, and the digest is not the pin. The test `psyq_mutant_ratan_index_off_by_one` passes.
- **Game code, private:** the tests with the label `private` need the three variables `SH2O_PS1_LIBGTE_OBJECTS`, `SH2O_PS1_LINK_MAP` and `SH2O_PS1_DATA`. `ctest --test-dir build/gcc -L private` passes with the three variables set. The identity digest of the inputs is the pin. The test `psyq_identity` finds that the object bytes of ratan2 have the sha256 of the header. The test `psyq_bodies` runs the object of ratan2 in an R3000 interpreter (`scripts/psyq_model.py`) and runs the sh2o function on the same cases. It compares 1,465 of the 1,465 cases and finds 0 differences. In 2 cases the object stops at a `break` and sh2o calls the break hook. The test compares these cases. The test `psyq_ratan2_pairs` runs 12,169 pairs of arguments: 0 differences, 2 with a `break`. With the mutant `ratan_index_off_by_one`, 894 of the 1,465 cases of `psyq_bodies` differ. When a variable is not set, each of these tests stops with exit code 77 (skipped).
- **SH-2 cross build:** `make cross`. `tests/sh2/psyq_static.txt` checks `src/sh2o_psyq.c` at `-Os` and `-O2`. The only undefined symbols are `sh2o_gte_read`, `sh2o_gte_write`, `sh2o_gte_command` and `__sdivsi3`. The object has 20 globals `sh2o_psyq_`, no `MAC.W` and no `SETS`. It has no SR write, no divide step and no constant in the SH-2 divider area. The check finds the planted count. `tests/sh2/psyq_suite_static.txt`: the suite object needs only the 19 bodies, the break hook, `sh2o_gte_read` and `sh2o_gte_write`.
- **SH-2 model, exact:** `make sh2-model`. In the native program and in the portable program, the chain of the 1,216 suite cases gives the pinned digest `0xE430E70B`. In both programs, the 6 known answers of `ratan2` hold. The harness then calls ratan2 directly for each of its 64 cases, and the chain of these calls also gives the pin. Program sha256: native `0fe2eaeb…`, portable `f3018762…`. These values changed when a commit added the list source `src/sh2o_list.c`, and again when a commit added the delegate source `src/sh2o_zam.c`. The figures did not change. With the option `SH2O_ZAM` off, the delegate source compiles to no symbol, and only its file name joins the symbol table. Before the delegate source, the values were native `70f26222…`, portable `33c04808…`. Before the list source, they were native `57620478…`, portable `b88d9745…`.
- **SR.S:** not affected. ratan2 does not use `MAC.W`: `src/sh2o_psyq.c` has no `MAC.W`, and ratan2 does not run MVMVA. The harness count for SR.S = 1 (199 of 1,216 suite cases) is a total for all the bodies.
