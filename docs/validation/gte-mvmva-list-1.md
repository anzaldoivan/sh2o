# Validation record: 2026-11-21 (host and SH-2 model, gte-mvmva-list-1)

Function `sh2o_gte_mvmva_list` in `sh2o/list.h`: n MVMVA commands in one call. A list is the in-order fold of its n singles (`sh2o_gte_mvmva`, record [gte-mvmva-1](gte-mvmva-1.md)). The GTE functions are described in [GTE.md](../GTE.md). The other records are listed in [VALIDATION.md](../VALIDATION.md).

- **Pins:** SH2ZAM `7f99eb70`, Yabause `7e38821d`, sh2eb-elf-gcc 13.2.0 in the pinned Yaul image (`ijacquez/yaul@sha256:b6d27220…`). Host compilers: GCC 16.2.1 and Clang 23.1.6.
- **Host, exact:** `make test` passes with GCC and with Clang. The test `list` gives the 88 vectors of `tests/list_oracle.h` (56,320 result bytes) through `sh2o_gte_write`, `sh2o_gte_mvmva_list` and `sh2o_gte_read`, with zero differences. `scripts/vectors_list.py` makes these vectors from the Python model (`scripts/gte_model.py`). The test `list` also runs the suite `tests/suite/sh2o_list_test_suite.c`: 256 runs, 2,144 items, 0 prefixes that differ from the singles (each item, all 64 registers), 238 of 238 planted reorders caught. These are the pins of `tests/suite/sh2o_list_test.h`. The list mutants (`list_mutant_<name>`, `tests/mutant.py`) each give a difference in vector 0, and their tests pass: `item_dropped`, `ir_not_sign_extended`, `mac_wrong_register`, `rows_swapped`, `vz0_not_loaded`.
- **The option:** `SH2O_ZAM` off. The list has no build switch, and the test `list` also runs in the build with the option on: `make test SH2O_ZAM=ON` passes with GCC and with Clang, with the same figures. In that build MVMVA can use the delegate (record [zam-mac3-1](zam-mac3-1.md)).
- **SH-2 cross build:** `make cross`. `tests/sh2/list_static.txt` (`src/sh2o_list.c`, at `-Os` and `-O2`): 57 instructions at `-Os` and 59 at `-O2`; the only undefined symbol is `sh2o_gte_mvmva`; the only global is `sh2o_gte_mvmva_list`; no `MAC.W`; no `SETS`, no SR write, no GBR, no divide step, no constant in the SH-2 divider area. The planted count is found. The suite `tests/suite/sh2o_list_test_suite.c` compiles in the native and in the portable build.
- **SH-2 model, exact:** `make sh2-model`. In the native program and in the portable program, the 88 vectors give zero differences, and the singles from the same image give the same out rows and the same 64 words. In each program one `sh2o_list_test_counts` call gives the pins: 256 runs, 2,144 items, 0 prefixes that differ, 238 of 238 reorders caught. `make sh2-model SH2O_ZAM=ON` gives the same results in each program. Program sha256: native `9cd5a8a5…`, portable `08294765…`; with the option: native `bada81ca…`, portable `44e6319d…`.
- **SR.S:** in the native program, MVMVA can use the `MAC.W` kernel `sh2o_k_mvb3_w` (record [k-mvb3-macw-1](k-mvb3-macw-1.md)). That kernel assumes SR.S = 0. The harness runs the 88 vectors again in the native program with SR.S = 1. The result is different for 18 of the 88 vectors without the option, and for 3 of the 88 vectors with the option. The library does not check SR.S. These counts are not a pass or a failure.
- **2026-11-22:** with SR.S = 1 the count is now 0. The library checks SR.S: record [k-mvb3-macw-2](k-mvb3-macw-2.md).
- **Planted difference:** with `--plant 0` the harness changes bit 0 of the first expected result byte of vector 0. The run stops with exit 1 and gives the first difference. With `--plant-count` the harness compares the counts with the pins where the item count is XOR 1, and the run stops with exit 1.
- **MODELLED cycles:** one list item is one `sh2o_gte_mvmva_list` call, from its entry to its return, divided by its n, over the 84 vectors with n of 1 or more. One single is one `sh2o_gte_mvmva` call, over the 656 items of the singles.
